# PWA初回問題取得の修正（DEV-11.03-8）

## 原因と変更

端末内登録を先に準備したschema2状態では、pack未保存でも保存操作が実行基盤の確認後に戻り、同期も解析待ちがreadyでなければ初回取得しなかった。問題0問・解析待ちなしでは手動同期も無効だった。

準備済み端末と明示的な手動同期で未保存packを取得し、保存操作は同期完了を待つ。0問でも手動同期を有効にし、手動再試行では直前の操作エラーを消す。保存先の照合・未送信回答・中断・端末内JSONの保護は既存engine/store/protocolを使い、形式や学習判定は変更しない。

## 検証

- 修正前に架空データの初回保存と手動同期の2経路で取得漏れ/無効ボタンを再現。
- 初回保存、初回手動同期、503後の再試行、以前保存した空packからの更新を追加。schema2とpack内容を確認し、通信停止後の再読込と復習開始も検証。
- `npm run check` / `npm run build` 成功。Python core全133件成功。
- Edge全182ケースは180件成功、P6の同一fixtureに起因する2件失敗。初回手動同期で空packが保存されると、その後は同期protocolが使われる。fixtureは同期要求にもpackだけを返していたため、実サーバーと同じphone_sync応答へ修正した。
- P6のWindows向け/iPhone向け2件を追試して成功（1.8分）。製品コードは791577cから変更せず、全182ケースの最終成功を確認した。一括実行で182件すべて成功したという意味ではない。
- `npm test`の構成要素を別実行。1460はCIの専用サーバーと私的な生成DBを使い、普段使い版を借用しなかった。実データ/URL/学習履歴は登録しない。
