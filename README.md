# KyokuLoop

対局後の気づきを反復学習へつなげる、完全な個人利用・非公開の四人麻雀ツール。販売・配布・公開サービス化は目的にしない。

現在は **P5 同期・復旧 DEV-11.01-5**。専用の `/phone/` で保存した復習記録を本人限定HTTPS経由でWindowsへ送り、受信確認・再送・複数端末の順序と期限再計算・ファイル復旧に対応する。技術検証済みで、実iPhoneの更新後の同期確認を待っている。

**P0の中核ゲート通過、P1のクイズ動線はユーザー確認済み**。P2では指定9レポート・両モデルの内部検証と原雀魂の5判断照合を実施。P3は固定日時と実データのprivate複製で復習・期限・復元を検証した。P4実機ゲートは2026-11-01にユーザーの成功回答で合格。P5の実iPhone更新後の同期確認は別途行う。

## 起動

Node.js 22.12以降とnpm、Python 3.10以降（標準sqlite3モジュールを含む）が必要。初回は `npm ci`。確認環境はWindows、既存のMicrosoft Edge。

```powershell
Set-Location E:\dev\kyoku-loop
npm run dev
```

[アプリを開く](http://127.0.0.1:1460/)。ポート1460は `sutbun/ai-dev/DEV-PORTS.md` に登録済み。loopback限定、使用中は他の番号へ自動変更しない。終了は起動したコンソールでCtrl+C。

iPhone用は先に `npm run build` を実行してから起動し、本人限定HTTPS経路で `/phone/` を開く。[P4の設定・保存と実機確認](docs/P4-OFFLINE-RESULT.md)を参照。

```powershell
npm run check
npm run build
npm test
```

`npm test` はビルド後にP0〜P5のPython・画面・オフラインテストを実行する。画面テストは既存Edgeで、Windows幅とiPhone 13相当の幅を使用。Safari/iPhone実機の検証とは異なる。生成データをprivateの一時SQLite/ブラウザプロファイルへ保存し、利用中のDBや実レポートを必要としない。Worker更新のテストはビルド済み静的ファイルを一時変更して最後に復元するため、必ず `--workers=1` で実行し、同時にビルドしない。GitHub Actionsは使用しない。

## 現在の範囲

- 「牌譜を追加」からNAGAのレポートURL / report_idを読み込むか、本人が利用できるJSON / JSON.gzを選ぶ。プレイヤーと基準NAGAタイプを選んで登録する。元の雀魂共有URLは任意の手動対応として保存し、本人席や元対局を自動推定しない。
- data_version=[1,0]、naga_version=[2,2]、game_type=0の4人カスタムレポートを対象とし、基準モデルはP0で検証したインデックス0/1。未知形式・破損局は登録せず、重み不明・自分のリーチ成立後等は学習候補にしない。
- 自分の手牌、河、副露・槓、リーチ、ドラ表示、本場、供託、点数を表示する。他家の隠し手牌や山は画面用データへ含めない。「収録手順」はJSONにあるイベントで、原牌譜の全手順・終了情報を完全に代替するという意味ではない。
- 候補重み差を合計100の分布で計算。各局の最上位を優先して最大10件を選び、再び差の降順に表示する。差が0の判断を水増ししない。勝率・期待損失ではない。
- 元レポート、取り込みURL、選択、正規化データ、学習登録は `D:/dev-data/kyoku-loop/private/app/kyokuloop.sqlite3` へトランザクションで保存。同じ入力の再取り込み・同じ対局の別モデルで既存の問題や履歴を置換しない。完全に同じ変換牌譜を対局IDの根拠にし、別の抜粋同士を同一対局とは推測しない。
- URL取得は既知のNAGAホスト・形式への通常HTTPS GETのみ。リダイレクト・認証・Cookie転用・NP消費・拡張制御を行わない。接続できない場合は理由とファイル選択を示す。
- 今日の期限が来た復習中の問題→手動の新規→自動の新規を優先して最大5問。初回は翌日以降。「今すぐ学ぶ」は自主練習として履歴を記録し、期限・連続理解回数を進めない（保留は出題を停止）。途中の選択・回答確定・進行もDBへ保存する。
- 定期復習で「理解した」が続くと3/7/14/30日後、5回目で卒業。「再復習」は0回に戻して翌日。「保留」は停止、「再開」はすぐ再開できる日へ（同日に定期記録済みなら翌日）、卒業後の「再学習」は新サイクルで開始する。日付はJSTの暦日。NAGAとの同牌種と自己評価を別に扱う。
- 回答・日時・端末・学習サイクルは追加型のイベントとして保持。二重送信を排除し、取消も元履歴を消さない。履歴を持つ手動保存問題は保存取消で削除せず、出題停止にはライブラリの「保留」を使う。
- 学習画面の「バックアップと復元」で保存・圧縮ファイルのダウンロード・ファイル選択・内容確認が可能。復元は既存の追加データを残す方式で、分岐した履歴や破損は適用しない。保存先はprivate/app/backups。別媒体で保管する場合はダウンロードしたファイルを移す。ファイル選択は20MB以下（展開後256MB以下）。
- [P1の架空データ試作](http://127.0.0.1:1460/?demo=1)はDEV-11.01-1の確認用として残す。5問クイズ・自己評価・4状態の操作とlocalStorageの既存進行はこの試作内のみ。実ライブラリと混ぜない。
- 旧麻雀ツールのコード・設計・UI・データは参照/再利用していない。

## P0のローカル照合

製品インポーターではなく、指定したファイルを読み取る技術検証ツール。ネットワークアクセスを行わず、結果はGit外の指定private領域に限って保存する。

```powershell
python tools/p0_verify.py D:\dev-data\kyoku-loop\private\p0-20261101\R7.json --seat 0 --model 0 --output D:\dev-data\kyoku-loop\private\p0-20261101\R7-verification
npm run test:p0
```

元の雀魂との同一性・本人席はこの内部照合だけでは証明できない。このCLI自体は評価の正規化や自動問題登録を行わず、P2では同じ検証器をアプリ用ストアから呼び出して使う。
