# Mortal結果の自動取り込み

Windowsホームの「Mortal 自動取り込み」で保存先を指定し、「このフォルダのMortal JSONを自動登録」を有効にして設定を保存する。初期候補は `D:/dev-data/kyoku-loop/private/mortal-inbox`。取り込み先はprivate配下の専用フォルダに限り、アプリのDB/バックアップ用フォルダやGit内は使えない。

以後、本人が通常のブラウザで保存したMortalの結果JSON/JSON.gzをそのフォルダ直下へ入れる。Windows側のKyokuLoopが起動していれば、ブラウザのKyokuLoopタブを閉じても取り込む。Windows停止中は取り込まない。再起動後は保存済みファイルも対象となる。

5秒ごとの観測で、サイズと更新時刻が3秒以上変わらないファイルを読み、読み込み前後の一致を確認する。保存途中の拡張子やサブフォルダは対象外。元ファイルは変更・移動・削除しない。対応版・局面・対象席・モデルを既存Mortal検証器で確認してから登録する。1回の走査で最大2件を処理する。通常の結果では保存完了後およそ5〜10秒と検証時間で反映する。

## 登録と元牌譜

- 自動取り込みを有効にすることが、フォルダ内の正常なMortal結果を登録する指定となる。ファイルごとの登録ボタンは不要。対象席とモデルはJSONの解析結果に固定する。既存の問題・回答・期限・中断位置を置き換えず、従来の重複防止と同一対局/席の最大3問を維持する。初回の定期復習は翌日以降。
- 結果JSONには元雀魂URLがない。日時・名前・ファイル名から推測しない。同じ全局牌譜のidentityと同じ対象席について、以前に本人が指定した元URLが一意にある場合だけ再利用する。複数候補や初回は未紐付けのまま登録し、ホームの該当結果の「元牌譜を選ぶ」で保存済み対局を選び「この対局へ紐付ける」。別の元URLへ上書きしない。
- 手動の場合は、解析待ちの対局行へファイル1つを直接ドロップできる。対局情報・元URL・解析対象席・モデルを確認し、「このプレイヤーで登録」で確定する。既存のファイル選択/URL入力も残す。複数ファイルや不正入力では登録しない。

## 失敗・停止・保存

同じ内容や名前違いの再保存は重複登録しない。各ファイルの状態は設定内へ最新20件を表示する。不正/未対応ファイルは登録せず、ファイルを修正・保存し直すと再検証する。取り込み処理自体の失敗やタイムアウト時は自動走査を停止し、設定を保存し直すまで反復しない。設定を無効にすれば次の走査を停止する。実行中の走査は完了まで待つ。

設定・取り込み台帳・停止通知はDBと同じprivateディレクトリの `mortal-inbox-settings.json`、`mortal-inbox.sqlite3`、`mortal-inbox-error.json` に保存する。元レポートと復習記録は従来のアプリDBへ入る。取り込み設定/台帳は学習DBバックアップの対象外で、復元先で必要なら有効化し直す。アプリDB復元後に台帳だけが残っていても、未登録の結果を重複扱いして失わない。

既存のWindowsプロセス内で動かし、新規サービス/自動起動は追加しない。バックグラウンドのPython処理を起動制御の処理中件数へ含め、正常終了時に次の走査を止める。iPhone用APIへフォルダ操作を公開しない。新しい解析依頼・外部HTTP取得・ブラウザログイン・拡張操作は行わず、既知403の取得経路も再試行しない。
