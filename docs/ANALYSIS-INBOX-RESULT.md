# 雀魂URLの解析待ち — DEV-11.01-6

元仕様3節/12節の未実装だった入口を、既存のホームと取り込み画面へ追加した。新しいナビゲーション階層は作らない。

## 動作

- iPhoneホームの「牌譜を追加」で共有URLを一度貼り、「保存」。問題を取得していない端末でも使える。IndexedDBの完了後に追加成功を表示し、受信確認前は「この端末に保存済み・未同期」。保存失敗では入力を残し、成功表示しない。
- 既知の雀魂共有URLだけを受理し、そのままローカル保持する。URLを解析目的でサーバーから取得しない。URL内のプレイヤー識別部分を除去せず、別の視点のURLを同じ対局だと推定しない。同じ完全URLの再送は一件にまとめる。表示する日時は保存日時であり対局日時ではない。未取得のルール/対局日時を作らない。
- 起動/通信復帰/フォアグラウンド/手動で本人限定のphone APIへ再送。WindowsのCOMMIT後に返ったURL/IDを照合し、IndexedDBで受信状態を保存する。URL原本は受信後も保持。通信中に追加した別URLは消さない。回答同期とURL同期は独立して試みる。
- Windowsホームに「解析待ち」。画面を開いた時点の一覧を表示し、「NAGAで解析」は元の雀魂URLを新タブで開く。NAGAへ共有URLをそのまま解析依頼する機能ではない。自動課金/拡張操作/認証操作はない。
- 初回の解析案内は「確認しました」後に自動表示を止め、「解析の手順」で再表示できる。「解析を依頼した」は本人の明示申告だけで依頼中表示にする。取り消し可能で、NAGA側の処理状況を観測したとは表示しない。
- 対象項目の「結果を登録」は既存のURL/JSON取り込みを開き、元URLを固定する。本人席と基準モデルは本人が選択。登録とキューへの紐づけを同じSQLiteトランザクションにする。異なる元URLへの既存レポートの付け替えは拒否。不正な結果・途中ディスク障害では成功にしない。
- 検証済みの結果と問題が存在すれば「学習準備完了」。問題候補がない場合は「検証完了（対象問題なし）」。iPhoneの次回同期で問題も更新する。まだ問題セットを取得していない端末も、準備完了を受信したら本体キャッシュを確認して初回取得する。保存済みの回答や進行をリセットしない。

## 保存と互換性

SQL列/表/版3、IndexedDB版1を維持。URLはSQLiteのstudy_settingsの専用analysis:接頭辞に保存し、既存の一貫したSQLiteバックアップへ含める。復元は欠損URL/リンクだけを追加し、新しい本人申告やリンクを消さない。リンクが別の元URLと衝突するバックアップは適用しない。

phone状態には省略可能なanalysis_queueを追加。旧P4/P5データはそのまま読み、書き換え前に構造を確認する。既存の「記録をファイルに保存」にURLも含む。URLだけのファイルも空の復旧先へ読み込め、受信確認をリセットして再送できる。Windowsの端末ファイル追加でもURLを回収可能。回答とURLはそれぞれ再送可能なトランザクションで追加し、途中失敗時は同じファイルで再試行する。

生URL・個人識別・原レポート・実回答はGitへ登録しない。実使用DBをリセットせず、AIの動作検証ではリポジトリ外private内の生成データだけを使う。

## 確認範囲

保存・不正URL/不正バッチの拒否・非増殖・再起動・結果の明示紐づけ・元URL衝突・結果保存途中の巻き戻し・候補なし表示・SQLite/phone JSON復旧を検証する。画面では、問題未取得でのURL保存→受信確認消失→オフラインプロセス再起動→再送→Windowsで本人申告/初回案内確認→架空JSON登録→iPhone問題取得を通す。容量不足時の成功非表示とphone APIの操作制限も検証する。
