# iPadで牌譜URLを一括コピー・テキスト保存・追加する

11.04-10。iPad Safariの確認用ショートカットで本人が25件取得できた経路を使う。表示中のDOMにある本人対象の公開リンクだけを読み取り、外部API、Cookie、サイト内部JS状態、未表示の全履歴、Mortal解析依頼を扱わない。

## 対局日時・順位・相手名も取り込む（11.04-11）

1. iPad KyokuLoopを右上の版表示から11.04-11へ更新する。
2. ホーム→牌譜を追加→「牌譜URLをまとめて追加」→「情報付き取得コード」を開き「コードをコピー」。コピー不可なら同じ欄のコードを手動選択してコピーできる。
3. 既存の「牌譜URLを保存」ショートカットの「WebページでJavaScriptを実行」のコードを**全部消して**貼り付ける。コード末尾の `})();` まで入る。入力「ショートカットの入力」、共有種類「SafariのWebページ」は維持する。コピー/日付/名前/txt保存のアクションは変更しない。[コードの正本](snippets/ipad-history-metadata-shortcut.js)。
4. Safariで牌譜屋を日本語表示にし、同じプレイヤーの履歴を表示して共有→「牌譜URLを保存」。出力はURLと対局情報を持つJSONテキストになる。既存の日時付き `.txt` 保存をそのまま使える。
5. KyokuLoopの「牌譜URLをまとめて追加」へ貼り付けるかtxtを選び「まとめて追加」。以前のURLが同じなら重複として扱い、情報がなかったものにだけ日時/自分の順位/相手3人の名前を補完する。「情報N件補完」と表示する。

表示行の日時、順位、4人の名前/点数、本人対象の牌譜リンクを同じ行で確認し、順位と点数の整合を検査できたものだけを付ける。別人を自分として除外しないよう、4人の牌譜リンクから対象URLを一意に確認する。構造違い/非表示/情報欠落/本人席を確認できない行はURLだけ残し、名前等を推測しない。全件読めた既存25URLなら「0件追加・重複25件・情報25件補完」となるが、実iPadの情報抽出件数は確認待ち。

既存の依頼中状態・解析結果とのリンク・学習記録・途中位置は変更しない。同じURLの保存済み情報と異なる内容は上書きせず、その一括追加を止めて知らせる。URLのみの既存txtも引き続き使える。同期で情報を送受信し、古いURLだけのACKで後から補完した情報を消さない。端末バックアップ/復旧も情報を保持する。Windows側も既存の情報保存先を利用し、SQL形式は変更しない。

## 初回: 取得ショートカット

既存の「牌譜URL確認」を複製し、「牌譜URLを保存」に名前を変更する。「共有シートに表示」と受け取り種類「SafariのWebページ」は維持する。Mortal結果JSON保存のショートカットは変更しない。

1. 最初の「WebページでJavaScriptを実行」は入力を「ショートカットの入力」にする。コードは [実用版](snippets/ipad-history-shortcut.js) に置き換える。確認用との違いは、対象外ページ/0件をエラーで止め、結果の見出しを付けずURLだけ返すこと。ネットワーク取得やページ操作は追加しない。
2. その後に次のアクションを順に置く。旧「結果を表示」は取り除く。

| アクション | 入力・設定 |
|---|---|
| クリップボードにコピー | 1の「JavaScriptの実行結果」。 |
| 現在の日付 | そのまま。 |
| 日付を書式設定 | 直前の「現在の日付」。日付フォーマット「カスタム」、書式 `yyyyMMdd-HHmmss-SSS`。 |
| 名前を設定 | **名前を付ける対象を1の「JavaScriptの実行結果」に戻す**。名前は `paipu-` + 直前の「フォーマット済みの日付」変数 + `.txt`。例 `paipu-20261104-083000-123.txt`。日付をファイル本文にしない。 |
| ファイルを保存 | 「名称変更された項目」。保存先を既存のMortalフォルダに固定。「保存先を尋ねる」オフ、「ファイルが存在する場合は上書き」オフ。 |
| 通知を表示 | `牌譜URLをコピーして保存しました`。ファイル保存の後に置く。 |

署名済みshortcutの自動配布は未対応。Windows生成の未署名ファイルをインストールできるとは案内しない。Apple標準のSafari共有から実行する。JavaScript許可は本人が端末の通常設定/確認画面で行う。サイトやOSによる拒否を解除する回避手順は追加しない。

## 毎回

1. Safariで本人の牌譜屋ページを開き、必要な対局履歴を表示する。
2. 共有→「牌譜URLを保存」。コピーと日時別txt保存が完了する。毎回最大500URL。スクロール前に消えた行の保持や全履歴の網羅はこの一度だけの取得では保証しない。
3. iPad KyokuLoop 11.04-10のホーム→「牌譜を追加」→「牌譜URLをまとめて追加」。
4. 「URL一覧」に貼り付けるか、「URL一覧のテキストファイル」で保存したtxtを選ぶ。「まとめて追加」を押すまで登録しない。
5. 「この端末にN件追加 · 重複M件」で端末保存が成立。同じURLは既存の解析状態/リンク/記録を維持する。Windows未接続でも保存し、後で既存の同期経路から送る。
6. 保存牌譜の「Mortalへ」で通常の入力済み画面を開き、本人が解析を送信する。Mortal結果JSONの取得・保存・登録は従来どおり。

1行1URL、UTF-8（BOM可）、CRLF/LF/CR可。空行は無視、ラベル「雀魂牌譜:」も可。最大500行、2MiB、端末の保存URL総数1000。11.04-11以降はWindowsと同じ `kyokuloop-history` version1の情報付きJSONも受け付ける。HTML・件数見出し・余分な説明行・未知のJSON形式は受け付けない。全行を検証してから1回のIndexedDBトランザクションで保存する。不正/容量不足/上限/書込失敗は一部登録せず、既存のURL・問題・回答・中断を保持。貼付内容は失敗時に残し、不正ファイルの選択ではそれまでの入力も保持する。

ファイル保存が失敗しても、先にコピーが成立していれば貼り付けは可能。保存成功の通知は出ない。保存先をリセットしたり、既存ファイルを上書きしたりせず、表示されたエラーを確認する。

## 確認範囲

本人はiPad Safariの25件抽出と、11.04-10での端末一括追加まで成功を回答済み。情報付き版のDOM抽出・名前/順位の表示、日時別txt保存とファイル選択の個別確認は別に扱う。ブラウザ不要の生成テストでURLの検査、重複、容量上限、IndexedDB保存/書込失敗、同期再送/復元を確認する。模擬IndexedDBによる検証は実Safariの保存耐久性の合格とは扱わない。
