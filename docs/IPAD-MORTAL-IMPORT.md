# iPad/iPhoneから取得済みMortal結果を登録

対象版: DEV-11.03-2（日常版11.03-2）。Mortalの結果JSON/JSON.gzをSafariなどで本人が取得済みであることを前提にする。新しい解析依頼やJSON取得の自動化、ショートカットは含めない。

## 操作

1. Windows側KyokuLoopを起動し、iPadを本人用Tailscaleに接続する。
2. Safariまたはホーム画面のKyokuLoopで、ホーム→「牌譜を追加」内の「解析結果を追加」を開く。
3. 「Mortal JSON / JSON.gz」で端末の「ファイル」から結果を選ぶ（20MB以下）。Windowsが形式を読み込み、解析対象席・名前・モデル・局数を表示する。この段階では登録しない。
4. 必要な場合だけ、受信済みの元牌譜を選び「Windowsに登録」。JSONの解析対象席とモデルは変更しない。元URLが確定できない場合は指定せず登録できる。
5. Windowsの登録ACK後、既存同期を完了待ちして問題を端末へ更新する。新規端末は問題パックとアプリ本体を保存する。定期復習の初回は従来どおり翌日以降で、その場では「今すぐ学ぶ」を利用できる。途中の復習がある場合はまずその続きになる。

取消・形式不正・局面不整合では結果を登録しない。MHTML/HTMLをJSONに改名したものは受け付けない。通信が戻れば「読み込みを再試行」や同じ「Windowsに登録」で再試行でき、二重登録しない。確認用tokenが30分で失効したときは「読み直す」。選択した元ファイルは端末の「ファイル」に保持し、端末へ結果JSONの自動再送キューは作らない。アプリを再起動した場合は同じファイルを選び直す。

「Windowsに登録しました」と端末の問題保存は別の結果として扱う。登録ACK後に問題更新が失敗してもWindows登録済み表示を保持し、「今すぐ同期」で更新を再試行する。既存の未送信回答・受信確認・途中セッションを消して新規パックを入れ直さない。新旧の同期待ちが重ならないよう直列化する。

## 専用境界

`POST /phone/mortal` を既存の本人用Tailscale/Origin/loopback制限の内側に設ける。公開操作は `inspect` と `register` のみで、それぞれフィールドを厳密に限定する。Windowsの `/api/local` と汎用action、任意URL・パス・対象席・モデルを外部から指定できない。既存 `/phone/api` の操作は拡張しない。

入力は20MB、JSONリクエストはbase64分を含め29MiBに制限する。既存のMortal形式/局面検証を再利用し、NAGAをこの入口から登録しない。既存問題パックの保存先IDとWindowsを照合し、登録時はプレビューが返した保存先IDを必須とする。結果にはランダムな短期tokenを用い、登録対象席/モデルはサーバー側でJSONから再決定する。元対局は本人指定か、全局identity/対象席が一致する既存一意リンクだけを使う。

SQL版3・端末schema1/policy2を維持し、元レポート/URL/名前/回答はrepo外privateに保存する。既知403の結果取得は行わず、認証回避・拡張自動操作・有料解析・新規サービス・Actionsを追加しない。自動検証と、実iPadでのファイル選択/操作感の合格は区別する。
