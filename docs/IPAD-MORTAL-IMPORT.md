# iPad/iPhoneから取得済みMortal結果を登録

11.03-4では端末内登録にも対応する。初回の「端末だけで使う準備」後の操作は [IPAD-STANDALONE.md](IPAD-STANDALONE.md) が正本。以下は準備前に使うWindows登録経路の仕様。11.03-3のiPad JSON選択→Windows登録は本人の「成功（登録できた）」で受入済み。
対象版: DEV-11.03-2（日常版11.03-2）。Mortalの結果JSON/JSON.gzをSafariなどで本人が取得済みであることを前提にする。新しい解析依頼やJSON取得の自動化、ショートカットは含めない。

Macなしで共有ショートカットを初回設定する手順は [iPadでJSONを保存](IPAD-MORTAL-JSON-SAVE.md)。本人のiPadで取得・保存したJSONを受領し、11.03-3では辞書変換後の同一全局log配列の重複を限定して正規化する。11.03-3の実iPadでのWindows登録は本人確認済み。端末内登録は別の実機確認として扱う。

## 操作

1. Windows側KyokuLoopを起動し、iPadを本人用Tailscaleに接続する。
2. Safariまたはホーム画面のKyokuLoopで、「牌譜」タブの「解析結果を追加」を開く。
3. 「Mortal JSON / JSON.gz」で端末の「ファイル」から結果を選ぶ（20MB以下）。Windowsが形式を読み込み、解析対象席・名前・モデル・局数を表示する。この段階では登録しない。
4. 必要な場合だけ、受信済みの元牌譜を選び「Windowsに登録」。JSONの解析対象席とモデルは変更しない。元URLが確定できない場合は指定せず登録できる。
5. Windowsの登録ACK後、既存同期を完了待ちして問題を端末へ更新する。新規端末は問題パックとアプリ本体を保存する。定期復習の初回は従来どおり翌日以降で、その場では「学習」の自主練習を利用できる。途中の復習がある場合はまずその続きになる。

取消・形式不正・局面不整合では結果を登録しない。MHTML/HTMLをJSONに改名したものは受け付けない。通信が戻れば「読み込みを再試行」や同じ「Windowsに登録」で再試行でき、二重登録しない。確認用tokenが30分で失効したときは「読み直す」。選択した元ファイルは端末の「ファイル」に保持し、端末へ結果JSONの自動再送キューは作らない。アプリを再起動した場合は同じファイルを選び直す。

「Windowsに登録しました」と端末の問題保存は別の結果として扱う。登録ACK後に問題更新が失敗してもWindows登録済み表示を保持し、「問題の更新を再試行」で更新だけを再実行する。新規端末で問題がまだ0件でも使える。既存の未送信回答・受信確認・途中セッションを消して新規パックを入れ直さない。新旧の同期待ちが重ならないよう直列化する。

## 元牌譜の自動紐付け（11.04-15）

元牌譜欄は「自動で紐付け（候補が1件の場合）」が初期値。JSONを選んで「この端末に登録」または「Windowsに登録」を押すと、保存済みの牌譜屋情報と照合し、一意の候補へ自動で紐付ける。候補の日時・順位・自分の点数・相手名を確認して、別の候補を手動指定する操作も維持する。

**追加順は問わない。** JSONを先に登録しても、後から牌譜屋の情報付きデータを追加・補完・同期した時点で未紐付け結果を再照合する。以前に端末内登録した結果も、原本を端末内で再検証して点数を補完する。Windowsでは保存済み結果を一覧取得時にも再照合する。JSONやURLの追加・原本再選択をやり直す必要はない。Windowsへ一度同期した結果の紐付けが後から決まった場合は、次の同期で同じ結果へ紐付けだけを追加する。

照合条件は **4人の最終点数・自分の点数・自分の順位が一致するURLが1件** であること。4人分は表示順に依存せず照合し、同点時は元の席順で順位を計算する。名前は匿名でも利用できる。日時と相手名は候補表示用で、Mortal JSONとの日時一致を主張しない。名前だけでは自動確定しない。全局identity/対象席が同一の既存リンクを優先し、既存の紐付けは上書きしない。同じURLを異なるgame/seatの結果へ自動割当しない。候補が複数、または異なる結果が同じURLを競合する場合は未紐付けで保持する。URLの重複は候補数を増やさない。同じgame/seatの別モデルは同じURLを共有できる。

最終局の開始点数からリーチ支払いを引き、全和了/流局の増減を加算する。mjaiと埋め込み編集logの結果が一致し、4人の合計が100,000点になる場合だけ点数を使う。増減欠落・終局不明・未精算の供託などでは点数で紐付けない。手動選択と未紐付け登録は引き続き利用できる。

端末の点数ヒントはLocalImportの任意情報であり、material/既存ID/評価は変更しない。バックアップ復元時は原本の再計算とヒントを照合する。古いヒントなし記録も受け付ける。自動確定は同一点数の偶然の衝突を完全に排除するものではなく、本人承認の一意候補照合として扱う。JSON保存・牌譜屋情報取得のショートカット変更は不要。

## 登録後の確認（11.04-17）

登録完了欄で「この端末に登録しました」または「Windowsに登録しました」と、元牌譜の紐付け結果を別々に表示する。紐付いていれば **元牌譜に紐付け済み** と対局日時・順位・自分の最終点数を表示する。重複した結果も現在の紐付けを確認できる。未紐付けは **元牌譜は未紐付けです**、旧版ACKなどで成否を取得できなければ未確認と表示し、候補数から成功を推測しない。

JSONを先に登録して後から牌譜情報を追加した場合も、その結果IDが保存牌譜に記録されたことを確認して完了欄を更新する。問題パックの更新や同期に失敗しても登録ACKの表示は残る。これは保存内容の表示だけで、候補判定・既存リンク・問題・学習履歴・バックアップ形式は変更しない。

## 専用境界

`POST /phone/mortal` を既存の本人用Tailscale/Origin/loopback制限の内側に設ける。公開操作は `inspect` と `register` のみで、それぞれフィールドを厳密に限定する。Windowsの `/api/local` と汎用action、任意URL・パス・対象席・モデルを外部から指定できない。既存 `/phone/api` の操作は拡張しない。

入力は20MB、JSONリクエストはbase64分を含め29MiBに制限する。既存のMortal形式/局面検証を再利用し、NAGAをこの入口から登録しない。既存問題パックの保存先IDとWindowsを照合し、登録時はプレビューが返した保存先IDを必須とする。結果にはランダムな短期tokenを用い、登録対象席/モデルはサーバー側でJSONから再決定する。元対局は本人指定、全局identity/対象席が一致する既存一意リンク、または上記の一意点数候補を使う。

SQL版3・端末schema1/policy2を維持し、元レポート/URL/名前/回答はrepo外privateに保存する。既知403の結果取得は行わず、認証回避・拡張自動操作・有料解析・新規サービス・Actionsを追加しない。自動検証と、実iPadでのファイル選択/操作感の合格は区別する。

## 複数JSONの追加と保存牌譜の削除

1件のJSON確認画面では、点数・順位が一致する候補が1件なら元牌譜を初期選択し、選択欄の下に「紐付け先（自動選択）」と対局日時・順位・本人点数・対戦相手を表示する。そのまま「この端末に登録」または「Windowsに登録」を押せば手動選択なしで自動紐付けする。保存には既存の自動照合と競合防止を使い、初期選択を手動指定として扱わない。複数候補は各内容と手動選択が必要な旨を表示する。登録後の確定結果は従来の完了欄で確認できる。

「牌譜」→「解析結果を追加」→ファイル選択で複数のMortal JSON / JSON.gzを選び、「選択した○件をまとめて登録」を押す。1回50ファイル・合計100MB・1ファイル20MBまで。既存の照合で一意な元牌譜へ自動で紐付け、各ファイルの登録結果を表示する。失敗分だけ再試行できる。

保存牌譜は左の選択欄で1件以上選び、一覧上の「選択した○件を削除」から確認して削除する。「全選択」は現在の状態フィルターに該当する全件（次ページ分も含む）。解析結果・復習問題・学習履歴は残る。同じURLを追加し直すと一覧へ戻せる。
