# PR #1 統合前レビューと実レポートの一連確認

2026-11-02（JST）。対象はmainの初期コミット `3e348a6` からPR #1の `cebb337` まで。実装の正本は `c351f90`、それ以降の変更は合格記録だけである。保存・取得・同期・復元を重点的に自己レビューした。別のレビュアーによる独立レビューを実施したという意味ではない。

## 一連の動作

本人席と元対局が既に照合されている既存レポートを、privateに読み取り専用で複製した。新しい有料解析や外部拡張の操作は行っていない。ライブDBとは別の空のSQLiteと専用Edgeプロファイルへ、アプリの通常画面から以下を実行した。

1. iPhone幅のホームで元の雀魂共有URLを保存し、隔離したWindows保存先で受信。
2. Windows幅の解析待ちから既存JSONを選択し、照合済みの本人席/基準モデルを明示選択して登録。
3. 重要局面から開くことと、元の検証済みデータと正規化された局面/手順/重要局面IDの一致を確認。
4. 同じ結果を再登録しても牌譜や学習問題が増えず、登録済みの結果へ戻ることを確認。
5. iPhone幅で問題を取得し、通信を切ってブラウザプロセスを終了/起動。問題と進行を読み、自主練習で一問回答。
6. 回答確定前の比較非表示、確定後の比較、自己評価、未送信表示を確認。通信を戻して同期し、Windowsの「局面と履歴」でも回答を確認。
7. 再同期しても同じ回答原本が保持され、自主練習の卒業加算は0のまま。
8. 隔離DBのバックアップを別の空DBへ復元し、元レポート/問題/URL/不変の回答原本と元DB識別子を保持。復元後の同じ回答の再送でも増殖しないことを確認。

全手順が成功した。これは実データを使ったEdge/Chromiumの確認であり、今回あらためて実iPhoneで実施したとは扱わない。実iPhoneの保存/再起動/同期とURL入口は、2026-11-01の本人合格が別途存在する。実使用DBは検証前後の対象全表のハッシュが一致し、SQLite整合性検査も成功。試験回答をライブへ追加していない。

| 対象 | 確認した境界 |

| ローカルAPI | loopback固定、厳密なHost/Origin、転送ヘッダーとクロスサイト要求の拒否。コマンド文字列を組まずPythonへ標準入力でJSONを渡す |

| 保存 | SQLiteの書込トランザクション、元対局リンクの競合再確認、再取り込みの安定ID、IndexedDBの完了後だけの保存成功表示 |

| PWA更新 | 実データをキャッシュへ入れず、アプリ本体のビルド整合を確認。クイズ途中の強制切替なし。旧世代を壊さないキャッシュ修復 |
