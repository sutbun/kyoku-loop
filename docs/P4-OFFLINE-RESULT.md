## アクセスと起動

Windowsは引き続き `127.0.0.1:1460`。`npm run build` の後に `npm run dev`（または `npm run preview`）で起動する。専用の `/phone/` は開発用HMRを含まないビルド済みPWAを返す。Windowsの画面とP1試作にはService Workerを登録しない。

iPhoneは本人のTailscale端末から専用HTTPSアドレスへ接続する。Serveのマウントは `/phone`、接続先は `http://127.0.0.1:1460/phone`。FunnelやLANへの全API公開は使用しない。ホスト名・本人ログイン名はrepo外の `D:/dev-data/kyoku-loop/private/phone-access.json` に保存する。

phone経路はloopback経由かつ期待するHTTPSホスト・Tailscale本人ヘッダー・同一Originに限る。問題のダウンロード以外のサーバー操作は拒否する。Windowsの書込みAPIはプロキシヘッダー付きの要求を拒否する。取得物にレポート本体、元URL、名前、他家の隠し手牌、山、未来の局面を含めない。

このPCのTailscaleは稼働し、本人のiOS端末が登録済み。ユーザーがServeを有効化した後、1460のphoneマウントを設定した。実HTTPS接続でphone画面200・実問題3問取得200、root/Windows API404を確認。ブラウザ上の実HTTPS画面でも本体と問題3問の保存完了を確認した。本人以外の拒否はヘッダーを使った自動テストで検証しており、別アカウントの実端末からの試験は行っていない。

開発サーバー側のホスト許可はprivate設定の1ホストだけを読んで追加する。プロキシと同じHost/本人/Originヘッダーでloopbackへ接続し、phone画面200・実問題3問取得成功・Windows API403を確認した。これはTLS/Tailscale実接続の検証を代替しない。

## 保存と復習

- Safariの共有からホーム画面へ追加し、そのアイコンで開いて「問題を端末に保存」。問題はIndexedDB、本体・CSS・牌の表示コード・アイコンはService WorkerのCache Storageへ保存する。外部フォント・CDN・外部画像は不要。
- 本体の全素材とページのビルド番号を照合し、問題の書込みトランザクション完了後に再読込みで一致確認できたときだけ「オフライン利用可能」と表示する。起動・画面復帰時にも再検査する。
- 選択・確定・進行・自己評価・取消を端末内で原子的に記録する。書込み要求の成功だけで完了扱いにせず、トランザクションの完了を待つ。失敗時は画面を進めない。
- Windowsと同じJSTの期限・連続理解・卒業・保留・再学習規則を使う。1回最大5問。回答前の出題用データから評価を除き、確定後に比較を表示する。
- 回答は固有ID・端末ID・サイクル付きの未送信イベントとして保持する。通信が戻っても送信済み扱いにしない。取消も追加記録で残す。
- 未送信イベントまたは途中の復習があるとき、再取得で問題や履歴を置換しない。本体のキャッシュ修復だけが可能。記録全体をJSONファイルにも保存できる。Windowsへ取り込む同期・復旧処理はP5で扱う。
- 保存容量の目安・保護要求の結果・保存失敗を表示する。ブラウザの永続保存要求は保証ではなく、端末容量不足やサイトデータ削除による消失の可能性を示す。
- 更新は途中の復習を強制再読込みしない。新しいWorkerは既存画面が閉じるまで待機する。コードの更新で問題・未送信イベントを削除しない。

## 技術検証

- Pythonで生成データからの最小問題パックと読取り専用の出力を検証。
- 固定日時で3/7/14/30日・5回卒業、同日/自主練習、取消、重複ID、未送信がある再取得の拒否を検証。
- EdgeのiPhone相当画面とprivateの一時プロファイルで、容量不足による問題保存/回答失敗、通信遮断、ブラウザプロセス終了と再起動、2問目からの再開、未送信記録保持を検証。
- 素材1件の欠落で利用可能表示が消えること、通信回復後の本体だけの修復、未送信を保持した新Workerへの更新を検証。API応答をCache Storageへ保存しないことも確認。
- ライブDBをprivate内へSQLite backup APIで複製し、実判断3問を検証。元DBの回答履歴0件を変えず、実学習と架空の評価を混ぜていない。

自動テストはEdge/Chromiumであり、Safari/iOSの保存・ホーム画面起動・端末再起動を代替しない。

`npm run check`・`npm run build` 成功。全体の `npm test` はPython52件・画面38件が成功。その後のホスト許可と初回失敗からの再試行の調整では、P4/端末エンジンの12件（desktop/phone）が成功。書込み要求成功後のトランザクションabortも追加検証した。最後の再起動案内文の調整後に再ビルド成功。
