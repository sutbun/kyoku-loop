# iPadの共有からMortal JSONを保存する（手順 v1）

対象: 本人がSafariで開ける解析済みMortal結果。Macなしで、iPadの「ショートカット」に最初だけ設定する。以後は **結果画面 → 共有 →「Mortal JSONを保存」→ 保存**。保存したJSONはKyokuLoop 11.03-2以降の「解析結果を追加」で登録できる。

この手順のURL変換・拒否条件はWindowsで架空入力により確認する。実iPadの共有入力・HTTP取得・JSON書き出し・ファイル選択は未確認であり、動作合格とは区別する。新しい解析は実行しない。

## 最初に1回だけ設定

1. iPadの **「ショートカット」→「＋」** を開く。
2. 名前を **「Mortal JSONを保存」** にする。
3. 詳細（名前横のメニュー、または情報ボタン）で **「共有シートに表示」** をオンにする。受け取る種類は **「URL」だけ** にする。Safariのページ本文や画像は受け取らない。[Apple: 別のアプリから起動](https://support.apple.com/guide/shortcuts/launch-a-shortcut-from-another-app-apd163eb9f95/ios)、[入力の種類](https://support.apple.com/en-gb/guide/shortcuts/apd7644168e1/ios)
4. 下表の順にアクションを追加する。アクション内の青い入力部分をタップして「変数を選択」を使うと、前のアクションの結果を指定できる。表の「入力」を省略しない。iPadOSによってラベル・配置が少し異なる場合がある。

| 順 | 追加するアクション | 設定・入力 |
|---|---|---|
| 1 | リストから項目を取得 | 入力「ショートカットの入力」、取得「最初の項目」。複数URLを自動巡回しない。 |
| 2 | テキストを置き換え | 入力は1の結果。下の「検索」「置換後」を貼る。「正規表現」をオン、「大文字/小文字を区別」をオン。 |
| 3 | テキストを照合 | 入力は2の結果。下の「照合」を貼る。「大文字/小文字を区別」をオン。 |
| 4 | もし | 3の「一致」が **「値がある」**。5〜12をこの「もし」の真側に入れ、13を偽側に入れる。 |
| 5 | URLの内容を取得 | URLは3の「一致」。方法 **GET**。ヘッダー・本文は設定しない。 |
| 6 | 入力から辞書を取得 | 入力は5の「URLの内容」。HTML等ならここでエラーになり、保存へ進まない。 |
| 7 | 辞書の値を取得 | 入力は6の「辞書」、キー **`engine`**。 |
| 8 | もし | 7の「辞書の値」が **`Mortal` と等しい**。9〜11を真側に入れ、12を偽側に入れる。 |
| 9 | 入力からテキストを取得 | 入力を **6の「辞書」** に戻す。7の「Mortal」という文字だけを保存しない。 |
| 10 | 名前を設定 | 入力は9の「テキスト」、名前 **`mortal-result.json`**（拡張子まで含む）。 |
| 11 | ファイルを保存 | 入力は10の結果。 **「保存先を尋ねる」オン、「ファイルが存在する場合は上書き」オフ**。 |
| 12 | （8の）その他 | 「アラートを表示」を追加し、文言 **「Mortalの結果JSONではありません。保存しませんでした。」**。その後「もしの終了」。 |
| 13 | （4の）その他 | 「アラートを表示」を追加し、文言 **「対応するMortal結果画面のURLを共有してください。」**。その後「もしの終了」。 |

5のGETはApple標準アクションを1回使う。設定自体は[AppleのGETの案内](https://support.apple.com/ja-jp/guide/shortcuts/apd58d46713f/ios)に基づくが、Mortal側がShortcutsからの取得を許すことの証明ではない。

### コピーする文字（そのまま貼る）

「テキストを置き換え」の **検索**:

```text
^https://mjai\.ekyu\.moe/(?:(?:killerducky/\?data=(?:/|%2[Ff])report(?:/|%2[Ff])|report/)([a-f0-9]{16})\.json|progress\?task=([a-f0-9]{16}))$
```

**置換後**:

```text
https://mjai.ekyu.moe/report/$1$2.json
```

「テキストを照合」の **パターン**:

```text
^https://mjai\.ekyu\.moe/report/[a-f0-9]{16}\.json$
```

2で変換し、3〜4で宛先全体を検査する。未対応URLをそのまま「URLの内容を取得」へ渡さない。対象は `killerducky/?data=/report/…json`（スラッシュの%2F表記も含む）、同サイトの `/report/…json`、`/progress?task=…` の限定形式。断片・追加クエリ・別ホスト・ログイン画面には対応しない。progressは解析完了済みの場合だけ使う。

## 実行と登録

1. Safariで、すでに解析が完了したMortalの結果画面を開く。
2. **共有 →「Mortal JSONを保存」**。初回に当該サイトへの接続確認が出たら、宛先が `mjai.ekyu.moe` であることを確認する。今回のショートカットはWebページでJavaScriptを実行しないため、その設定変更は不要。
3. 保存画面で **「このiPad内」→「ダウンロード」** などを選び、最終ファイル名が `.json` で終わることを確認して「保存」。同名ファイルがある場合は別名を付け、既存ファイルを上書きしない。
4. KyokuLoop端末版のホーム→「牌譜を追加」内の **「解析結果を追加」→「Mortal JSON / JSON.gz」** で今のファイルを選ぶ。対象席・モデル・局数のプレビューが出れば、JSONとして読み込めた確認になる。WindowsとTailscaleを接続して使う。
5. **「Windowsに登録」**。「登録しました」または「登録済みの結果です」で成功。同じ結果の再登録で問題・回答は増殖しない。

辞書をテキスト化して保存するので、元ファイルの空白やキー順序は変わる可能性がある。KyokuLoopはJSON値から同一性を判定する。iPadの実際の書き出しが内容を保持できたことは、4のWindowsプレビューと登録結果で別途確認する。[Apple: 辞書とJSON](https://support.apple.com/en-me/guide/shortcuts/apd43b69f337/ios)

## 失敗したとき

- **401/403・アクセス拒否・本人確認**が出たらこの取得を止める。設定の変更、Cookieの持込み、ヘッダー偽装や連続実行はしない。表示された文言だけを知らせる。
- HTML・JSON変換エラー・「Mortalの結果JSONではありません」の場合も保存できたとは扱わない。通常のSafariで直接JSONリンクから本人がダウンロードする方法を使えるか別途確認する。
- 保存はできてもKyokuLoopで読み込めなければ、ファイルを保持し、表示されたエラーを知らせる。拡張子だけ変えて再登録しない。

取得前にJSONリンクへ移動するだけの方式へ勝手に変更しない。Windowsで既知の403取得を再開しない。標準HTTPアクションのリダイレクト・最終ステータスをこの手順が独自に制御するとは主張しない。

## 配布の制約

本人は **Macなし・iPadで初回設定** を選択済み。Windows生成の未署名 `.shortcut` を「追加するだけで使える」とは案内しない。Apple端末からの正規共有／署名は[配布調査](IPAD-SHORTCUT-DISTRIBUTION-RESEARCH.md)を参照。実牌譜URL・結果JSON・本人の保存先はGitへ含めない。
