# 牌譜屋から一括追加

DEV-11.02-8。普段のブラウザで表示できる対局のAIレビューリンクを集め、クリップボード経由でKyokuLoopへ追加する。APIや専用ブラウザで拒否された取得を再試行する機能ではない。

iPadは11.04-10から、Safariショートカットによる一括コピー・日時別txt保存と端末内一括追加に対応する。[iPadの手順](IPAD-BULK-IMPORT.md)。

## 使い方

1. WindowsのBraveでKyokuLoopのホームを開き、「牌譜屋から一括追加」を開く。
2. 「牌譜URLを一括取得」をブックマークバーへドラッグする（初回のみ）。バーが非表示ならCtrl+Shift+Bで表示する。
3. 牌譜屋を日本語表示にし、自分のプレイヤー履歴ページで登録したブックマークを押す。
4. 表示中の対象URLが「取得N件」となる。古い対局も必要なら、自分でスクロールして表示する。取得済みのリンクは画面から消えても保持する。
5. 「KyokuLoopへコピー」を押し、KyokuLoopの「一括データ」へ貼り付けて「まとめて追加」。
6. 一覧の「Mortalへ」で、対象URLを入力済みのMortal日本語画面を開く。解析の送信は本人がMortal側で行う。

「URLだけコピー」は改行区切りのURLをコピーする。ほかの方法で既に取得した雀魂URLを、1行に1件で貼り付けることもできる。「雀魂牌譜:」付きの行も既存と同じ規則で正規化する。

コピーがブラウザに拒否された場合は、取得パネルにデータ欄を表示する。その欄でCtrl+Cを押してコピーする。ブラウザのセキュリティ警告やサイトの制限を解除する手順は含めない。

## 取得対象と制約

- `amae-koromo.sapk.ch` と公開ミラー `saki.sapk.ch` のプレイヤー履歴ページのみ。
- 表示されたAIレビューリンクの `url` 引数にある、日本版雀魂の共有URLのみ。対象プレイヤーの `_a...` を保持し、選択中プレイヤーのリンクと照合する。
- URLを推測しない。UUIDを隠した対局やAIレビューリンクのない対局は取得しない。
- 読み取れる行には日時・順位・対戦相手も付ける。画面構造からそれらを確認できない場合はURLのみ。元の牌譜本体やMortal解析結果を取得するものではない。
- 1回500件、入力2MiBまで。KyokuLoopの保存URL全体は一括追加後1000件まで。
- ページ内移動でプレイヤー等が変わったら収集を止め、取得済み分だけコピー可能にする。終了ボタンで監視と表示を破棄する。
- スクロールの自動操作、fetch/XHR、Cookie/認証情報/サイト内部のJS状態の読み出し、制限回避、Mortalの自動送信はない。
- 東風と判定できるメタデータにはMortalボタンを出さず「東風は対象外」とする。URLのみの場合はルールを判別できないため、Mortal側の対応範囲を本人が確認する。

## 保存と復元

全件の形式と対象プレイヤーを検証してから、1トランザクションで追加する。不正な行があれば全体を拒否し、貼り付け欄と既存の記録を保持する。同じURLは重複追加せず、既存の依頼中・紐づいた解析結果・問題・回答・中断位置を変えない。

日時等は既存SQLite `study_settings` の `paipu-meta:` 名前空間へ保存し、URL保存と同じトランザクションで確定する。SQL版3と既存テーブル/列を維持する。一貫したSQLiteバックアップへ含め、復元時は既存メタデータや本人の依頼状態を上書きしない。個人ページURL・ID・名前・実牌譜URL・履歴はGitへ入れない。

日時等を含む構造化一括データはWindows側の機能。11.04-10から端末版も改行URLテキストの貼付/UTF-8 txt選択で一括保存できる。既存オフライン保存・同期の方式を維持し、外部サイトからの直接書き込み口やCORS許可は増やさない。

## 検証範囲

架空ページで実際のJavaScriptリンクを起動し、DOMの追加・重複・コピー・コピー拒否・ページ移動停止を確認する。KyokuLoopの実Python/SQLite境界で、一括保存・全体拒否・既存記録保持・バックアップ復元を検証する。

実際のBraveでのブックマーク登録、サイト自身のCSPやブラウザ設定を含む実ページでの起動・コピーは、本人の確認と自動試験を区別する。未確認の実ページ成功を宣言しない。
