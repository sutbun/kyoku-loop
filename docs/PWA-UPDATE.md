# バージョン表示から更新

11.03-5から、端末版の右上のバージョン表示が更新ボタンになる。新しいバナー・カード・管理欄のボタンは追加しない。ヘッダーの高さも維持する。

- 起動時や画面に戻ったとき、Windowsへ接続できれば新しい版を調べる。アプリ本体とオフライン用実行基盤を保存し、更新可能なら同じ版表示に「↑」を付ける。
- バージョン表示を押すと更新確認から切替まで進む。新しい版がなければ同じ場所に「最新版」、接続できなければ「接続を確認」と表示する。更新確認には通常のWindows/Tailscale接続を使う。
- 保存・同期・JSON登録確認中や未保存URLがあるときは切り替えない。復習画面では「ホームで更新」と表示し、ホームから更新する。保存済みの復習の続きは残す。
- Safariなど他の画面でも開いている場合は、全画面で保存途中の処理がないことを確認してから切り替える。編集中や旧版の画面が応答できない場合は「他の画面を確認」。その画面の処理を終えるか閉じてから版表示を押す。
- 準備中の通信断・ファイル不整合・容量不足では切り替えず、現在の版を継続する。再接続後に同じ版表示から再試行できる。

更新はアプリの静的ファイルだけを対象とする。元JSON・未同期の回答・途中の復習を含むIndexedDBの保存形式は変更せず、消去もしない。未同期記録の送信完了を更新の条件にはしない。実行基盤が同じ場合は保存済みのファイルを検証して再利用する。

この機能を導入する最初の更新（11.03-4以前から）だけは、通信ありでSafariとホーム画面のKyokuLoopを両方閉じて開き直す。サイトデータは消さない。以後は版表示から操作する。

## 技術上の保持条件

Service Workerのinstall時にshellの世代一致と実行基盤のサイズ/SHA-256を検査する。本人の版ボタン操作後、対象の全windowへ確認し、各windowの保存処理がないこととUIの待機状態を確かめる。短時間の書込みロックを取得してからskipWaitingで切り替え、controllerchangeで開き直す。拒否・無応答ではロックを解放し、現在のworkerを維持する。

切替時に新しく開いた画面を検出した場合もいったん中止する。境界で新controllerと古いHTMLが同居した場合は、次の版ボタン操作から現在のcontrollerへ再読込を要求できる。直前の静的cacheも残し、古いhashのasset参照を保護する。確認用ロックは永続保存しない。

初回導入と更新後の実iPad操作の受入は、Edgeでの生成データ/実workerの検証とは分けて記録する。
