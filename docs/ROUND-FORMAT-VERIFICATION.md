# 局進行の生成検証

2026-11-02 JST。`tests/test_p2_round_formats.py`で、取り込み・局面投影・復元の局進行に対する検証を追加した。アプリ本体・依存・SQL/IDB・UI・バージョンは変更していない。

## 架空データの範囲

4人の初期手牌と物理枚数に収まる牌から、各局70回のツモ/打牌を生成する。各局はその局の親から始め、全員ツモ切りとする。赤5を含み、4席すべてに手牌内の候補と既知スケールの重みを付ける。局間の点数移動・テンパイ/流局判定・終局条件・順位計算は検証対象外であり、点数は各局開始時点のスナップショットとして扱う。

| 生成ケース | 確認内容 |
|---|---|
| 東1〜東4を4席それぞれで投影 | 4局を切り捨てず、親の巡回に対応する自風、実打牌、14枚の手牌、ドラを確認。他家の隠し手牌を投影へ含めない |
| 東4までの登録 | 重要局面は最大10、4局それぞれの代表を保持し、自動学習登録は最大3。東4を失わない |
| 東1の連荘/供託 | 同じ局番号でも本場と供託・開始点を保持し、別の判断IDになる |
| 東4の後の南1 | 4局で打ち切らず南1と場風/自風を保持する |
| 最後の局だけ番号/本場/供託が不整合 | レポートを拒否し、先行する正常局のレポート/問題/原本も部分保存しない |
| バックアップ・復元・再取り込み | 問題/判断ID、回答履歴、途中セッションを保持し、再登録で増殖させない。隔離した生成DBだけを使用 |
| 東1〜南4 | 同じ規則で8局を保持し、重要局面最大10の中に各局の代表を含める |

追加7件の集中実行は成功。既存コードに対して検証を追加したものであり、故意に既存コードを削除して失敗を作ったものではない。check/buildとPython全83件も成功。アプリ本体が同一コードであることを差分で確認し、画面60件/起動制御6件の既存成功証拠を再利用した（今回はブラウザテストを再実行していない）。詳細は共有AIのevidence/round-formats/verification.mdに記録する。

## 実牌譜との区別

これで実際のNAGA東風レポートの形式、ルール情報、雀魂原対局との一致が確認できたことにはならない。四つの東場を持つ生成した変換データの処理が対象であり、実東風サンプルの独立照合は未確認のまま維持する。局末イベント、鳴き/槓/リーチの新しい組合せ、対応外モデル/データ版への確認範囲も広げない。[MVP照合](MVP-ACCEPTANCE.md)を参照。
